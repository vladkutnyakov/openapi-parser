# Правила генерации (хуки)

Генератор по умолчанию выдаёт классический TypeScript: необязательные поля через `?`, enum как union литералов, точки с запятой в конце строк. Хуки позволяют заменить эти конвенции своими: вы пишете небольшой объект с методами на JavaScript, а генератор спрашивает у него, как отрендерить каждое поле, тип и комментарий.

Редактор открывается кнопкой **⚙** в верхней панели. Изменения применяются сразу, с живым предпросмотром выбранного эндпоинта. Кнопка **«Вставить образец»** подставляет в редактор все доступные хуки, каждый из которых воспроизводит поведение по умолчанию, — это самый быстрый способ начать.

## Как это работает

Генератор сам разбирает OpenAPI-спеку: раскрывает `$ref`, собирает массивы, `allOf`/`oneOf`, вложенные объекты, определяет обязательность полей. Результат этой работы он передаёт хукам в виде готовых данных, а хук решает, **какой текст** из них получится.

Ключевой принцип: **хук получает «чистый» тип — без `?` и без `| null`, добавленных по конвенции**. Дописать их решает сам хук. Конвенции по умолчанию живут в fallback-ветке генератора, поэтому любой хук может их полностью отменить.

Оговорка: если `| null` стоит в самой спеке (`nullable: true` в 3.0, `type: [..., 'null']` в 3.1), он уже входит в `f.type` — это факт схемы, а не конвенция. Отличить такой случай можно по `f.nullable`, а не дублировать `| null` помогает проверка `type.endsWith(' | null')`.

Если хук не задан или вернул `undefined`, работает поведение по умолчанию. Это позволяет переопределять точечно: например, задать только `docs`, а остальное оставить как есть.

## Формат кода

Код — это **выражение-объект в скобках**:

```js
({
  field(f) {
    return `${f.indent}${f.key}${f.required ? '' : '?'}: ${f.type};`
  },
})
```

Скобки обязательны — без них `{` читается как блок кода, а не объект. Пустой код означает «использовать правила по умолчанию» (классический TS).

Доступны только `field`, `scalar`, `typeName`, `declaration`, `docs`. Лишние ключи — ошибка: под редактором появится сообщение со списком неизвестных имён. Известные хуки при этом всё равно подхватываются, так что опечатка в одном имени не выключает остальные.

## Хуки

### `field(f)` — строка одного поля

Вызывается для каждого поля интерфейса, а также для path- и query-параметров.

| Поле | Тип | Описание |
|---|---|---|
| `f.key` | `string` | Имя поля |
| `f.type` | `string` | Готовый TS-тип без `?` и без конвенционного `\| null` (см. оговорку выше) |
| `f.required` | `boolean` | Есть ли поле в `required` схемы |
| `f.nullable` | `boolean` | `nullable: true` (3.0) или `type: [..., 'null']` (3.1) |
| `f.source` | `'response' \| 'body' \| 'query' \| 'path'` | Откуда пришло поле |
| `f.indent` | `string` | Отступ — верните его в начале строки |
| `f.schema` | `object?` | Исходная схема поля из спеки |
| `f.docs` | `string[]` | Части JSDoc: description, enum-литералы, format, default |

Возврат: строка целиком — включая отступ и завершающую точку с запятой. Генератор ничего к строке не дописывает: что вернул хук, то и попадёт в вывод. По умолчанию (без хука) строка выглядит как `${f.indent}${f.key}${f.required ? '' : '?'}: ${f.type};`.

```js
({
  // Тот же классический стиль, что и по умолчанию, но без точки с запятой
  field(f) {
    return `${f.indent}${f.key}${f.required ? '' : '?'}: ${f.type}`
  },
})
```

Ключ поля хук получает «как есть» — генератор не оборачивает его в кавычки. Если в спеке встречаются имена, невалидные как идентификаторы (`X-Total-Count`), кавычки ставит сам хук; в дефолтной ветке это делается автоматически.

`f.source` — главный инструмент: он позволяет применять разные конвенции к ответам и запросам.

```js
({
  field(f) {
    // в ответах всё обязательное, необязательное — через | null
    if (f.source === 'response') {
      const type = f.required ? f.type : `${f.type} | null`
      return `${f.indent}${f.key}: ${type}`
    }
    return `${f.indent}${f.key}${f.required ? '' : '?'}: ${f.type}`
  },
})
```

### `scalar(s)` — примитив или enum в TS-тип

Вызывается для `string`, `number`, `integer`, `boolean` и для схем с `enum`.

| Поле | Тип | Описание |
|---|---|---|
| `s.type` | `string?` | `'string'`, `'integer'`, `'number'`, `'boolean'`; в 3.1 из массива типов берётся первый не-`null` |
| `s.format` | `string?` | `'int64'`, `'date-time'`, … |
| `s.enum` | `unknown[]?` | Значения enum, если заданы |
| `s.source` | `FieldSource` | Как в `field` |
| `s.schema` | `object` | Исходная схема |

Возврат: строка типа либо `undefined` для поведения по умолчанию.

Схема с `enum` попадает сюда раньше, чем разбирается её `type`, поэтому у enum-ветки `s.enum` заполнен всегда, а `s.type` может отсутствовать.

```js
({
  scalar(s) {
    // строковый enum — просто string вместо union литералов
    // (сами литералы остаются в JSDoc-комментарии)
    if (s.enum?.length && s.enum.every(v => typeof v === 'string')) return 'string'
    // даты как отдельный тип
    if (s.format === 'date-time') return 'ISODateString'
    if (s.type === 'integer') return 'number'
  },
})
```

Хук применяется до сборки массивов и union, поэтому `ISODateString` из примера автоматически попадёт и в `ISODateString[]`. `| null` из спеки дописывается уже поверх результата хука — возвращать его самому не нужно.

### `typeName(n)` — имя типа

| Поле | Тип | Описание |
|---|---|---|
| `n.name` | `string` | Имя по умолчанию (для DTO — уже санитизированное) |
| `n.kind` | `'dto' \| 'response' \| 'body' \| 'query' \| 'path'` | Что именно именуется |
| `n.operationId` | `string?` | `operationId` из спеки |
| `n.status` | `string?` | Код ответа — только для `kind: 'response'` |
| `n.method`, `n.path` | `string` | Метод и путь эндпоинта |

```js
({
  typeName(n) {
    // GetUserByIdResponse200 → GetUserByIdResponse
    if (n.kind === 'response' && n.status === '200') {
      return n.name.replace(/200$/, '')
    }
    // все DTO с префиксом Api
    if (n.kind === 'dto') return `Api${n.name}`
  },
})
```

Имена DTO берутся из `components/schemas`, то есть это те же имена, которыми оперирует бэкенд. Невалидные идентификаторы (`PageDto«UserDto»` от springfox) санитизируются **до** вызова хука — в `n.name` приходит уже пригодное имя.

Для `kind: 'dto'` имя служит ключом реестра типов: по нему генератор понимает, что этот DTO уже встречался, и не выводит его дважды. Поэтому переименование должно оставаться взаимно однозначным — если хук сведёт два разных DTO к одному имени, один из них потеряется. Вызывается хук на каждую встреченную ссылку, но результат обязан быть стабильным для одного и того же входа.

### `declaration(d)` — объявление целиком

| Поле | Тип | Описание |
|---|---|---|
| `d.name` | `string` | Имя (уже после `typeName`) |
| `d.kind` | `TypeKind` | Как в `typeName` |
| `d.body` | `string` | Тело: `{ ... }` для интерфейса, выражение для алиаса |
| `d.isInterface` | `boolean` | Интерфейс или алиас типа |
| `d.docs` | `string[]` | Уже отрисованные строки JSDoc самой схемы |

Возврат: объявление целиком. По умолчанию это `export interface ${d.name} ${d.body}` для интерфейса и `export type ${d.name} = ${d.body};` для алиаса.

```js
({
  declaration(d) {
    // type вместо interface везде
    return `export type ${d.name} = ${d.body};`
  },
})
```

`d.docs` приходят уже готовыми строками (их отрисовал хук `docs`) и передаются для справки: комментарий генератор ставит перед объявлением сам, независимо от того, что вернул `declaration`. Убрать комментарий у объявления можно только через `docs`, а не отсюда.

### `docs(d)` — комментарии

| Поле | Тип | Описание |
|---|---|---|
| `d.parts` | `string[]` | Части: description, enum-литералы, `format: …`, `default: …` |
| `d.indent` | `string` | Отступ |

Возврат: **массив строк** (каждая — отдельная строка вывода) или `[]`, чтобы убрать комментарии.

```js
({
  // многострочный JSDoc вместо однострочного
  docs(d) {
    if (!d.parts.length) return []
    return [
      `${d.indent}/**`,
      ...d.parts.map(p => `${d.indent} * ${p}`),
      `${d.indent} */`,
    ]
  },
})
```

Комментарии видны в интерфейсе, но кнопка «Копировать» всегда отдаёт код без них — поэтому отключать `docs` ради копирования не нужно.

## Пресеты

Наборы правил сохраняются как именованные пресеты через хранилище оболочки: в вебе это localStorage, в расширении VSCode — `globalState` (ключи `openapi-parser:presets` и `openapi-parser:active-preset`).

Встроенных пресетов два:

| Пресет | Код | Что даёт |
|---|---|---|
| `Классический TS (по умолчанию)` | пустой | Дефолты генератора: `?` у необязательных полей, union литералов у enum, точки с запятой |
| `Без комментариев` | `docs() { return [] }` | То же, что классический TS, но без JSDoc |

Встроенные пресеты доступны только для чтения: первая же правка создаёт вашу копию с суффиксом `(изменённый)` и переключается на неё. Свои пресеты можно переименовывать, дублировать и удалять; после удаления активным становится `Классический TS`.

Названия встроенных пресетов и комментарии в их коде следуют языку интерфейса: при переключении языка код в редакторе перепишется на другой язык. Меняются только комментарии — поведение пресетов на обоих языках одинаково, и это проверяется тестом. То же и с образцом по кнопке «Вставить образец».

## Ошибки

Ошибки не ломают приложение:

- **Ошибка компиляции** (синтаксис, не объект, хук не функция, неизвестные ключи) — показывается под редактором. Если код не скомпилировался, хуки не применяются вовсе: вывод возвращается к правилам по умолчанию.
- **Ошибка выполнения** (исключение внутри хука) — для этого элемента берётся значение по умолчанию, сообщение показывается под редактором один раз, даже если повторилось на сотне полей. Оно всегда на английском (`Hook "field": …`): внутри лежит сообщение движка JS, которое не переводится, — переводить одну рамку вокруг него смысла нет.
- После 20 ошибок выполнения хуки глушатся до конца генерации и включаются снова при следующей правке кода — чтобы сломанный код не тормозил интерфейс.

## Ограничения

- Код выполняется через `new Function` в том же контексте, что и приложение: в вебе это страница, в расширении — изолированный webview (без доступа к Node API и к extension host). Это локальный инструмент, но не вставляйте в него код, которому не доверяете.
- Хуки синхронные: `async`, `await` и промисы не поддерживаются.
- Доступа к другим полям спеки, кроме переданных в контексте, нет. Если нужного не хватает — обычно достаточно `f.schema`, где лежит исходная схема целиком.

## Рецепты

**Классический TS без точек с запятой и без комментариев:**

```js
({
  field(f) {
    return `${f.indent}${f.key}${f.required ? '' : '?'}: ${f.type}`
  },
  declaration(d) {
    return d.isInterface
      ? `export interface ${d.name} ${d.body}`
      : `export type ${d.name} = ${d.body}`
  },
  docs: () => [],
})
```

**Readonly-типы для ответов:**

```js
({
  field(f) {
    const prefix = f.source === 'response' ? 'readonly ' : ''
    return `${f.indent}${prefix}${f.key}${f.required ? '' : '?'}: ${f.type};`
  },
})
```

**Брендированные идентификаторы:**

```js
({
  scalar(s) {
    if (s.format === 'int64') return 'Id'
    if (s.type === 'integer') return 'number'
  },
})
```

**Все типы с префиксом и без `export`:**

```js
({
  typeName: n => `T${n.name}`,
  declaration(d) {
    return d.isInterface
      ? `interface ${d.name} ${d.body}`
      : `type ${d.name} = ${d.body}`
  },
})
```
