# openapi-parser

Локальный инструмент: находит эндпоинт в OpenAPI 3.x спеке (JSON) и генерирует готовые TS-типы — path/query-параметры, тип body, типы ответов и все задействованные DTO с оригинальными именами бэкенда.

Кнопка «Сравнить» у любого типа открывает панель диффа: вставьте свой тип из кода — приложение покажет по полям, что разошлось с контрактом (нет поля / лишнее поле / другой тип / другая обязательность). Сравнение семантическое: порядок полей, форматирование и порядок членов union не считаются отличиями.

Вывод сгруппирован в сворачиваемые секции (path- и query-параметры, тело запроса, ответы, DTO), у каждой своя кнопка копирования; Ctrl+F ищет по сгенерированным типам с подсветкой совпадений и переходом по ним.

Метод, путь и описание эндпоинта, статусы ответов и Content-Type тела и ответов рисует интерфейс, а не комментарии внутри типа: в коде остаётся только то, что объясняет сам тип. Content-Type виден всегда — по сгенерированному TS `multipart/form-data` неотличим от JSON, а отправляются они по-разному.

Работает в двух видах: как локальная веб-страница и как расширение VSCode (отдельная панель прямо в редакторе).

## Запуск веб-версии

```bash
npm install
npm run dev
```

Открыть http://localhost:5173, в верхнем поле указать источник спеки:

- путь к локальному файлу: `C:\specs\api.json` или `packages/core/tests/fixtures/sample-spec.json`
- URL: `http://backend-host/v3/api-docs` (CORS не мешает — спеку скачивает dev-сервер, а не браузер)

Источник запоминается в localStorage и подставляется при следующем запуске.

Выбранный эндпоинт (`m`), фильтр по методу (`f`) и строка поиска (`q`) хранятся в hash URL (`#/users/{id}?m=GET&f=POST&q=user`) — состояние переживает F5, работают кнопки «назад/вперёд», ссылкой на конкретный эндпоинт можно поделиться с коллегой.

## Расширение VSCode

Ничего хостить не нужно: расширение работает целиком локально, спеку читает сам редактор.

```bash
npm run build:vsix
code --install-extension apps/vscode/openapi-parser.vsix
```

Дальше — команда «OpenAPI Types Tools: Open panel» из палитры (Ctrl+Shift+P). Панель наследует тему редактора, копирование идёт в буфер VSCode, а кука для закрытых авторизацией спек хранится в защищённом хранилище VSCode.

Для разработки — F5 в этом репозитории: откроется Extension Development Host с установленным расширением.

## Правила генерации (кнопка ⚙)

Конвенции проекта задаются JS-хуками. Пресеты («Классический TS», «Без комментариев» + свои) хранятся в localStorage, редактор показывает живой предпросмотр на текущем эндпоинте. Кнопки «Из файла» / «В файл» загружают и сохраняют правила `.js`-файлом — так общий стиль команды можно держать в репозитории.

```js
({
  // f: { key, type, required, nullable, source, indent, schema, docs }
  //   source: 'response' | 'body' | 'query' | 'path'
  //   type — чистый тип, без ? и | null: что дописать, решает хук
  field(f) {
    return `${f.indent}${f.key}${f.required ? '' : '?'}: ${f.type};`
  },
  scalar(s) {},      // { type, format, enum, source, schema } → строка типа
  typeName(n) {},    // { name, kind, operationId, status, method, path }
  declaration(d) {}, // { name, kind, body, isInterface, docs }
  docs(d) {},        // { parts, indent } → массив строк ([] чтобы отключить)
})
```

Любой хук можно опустить, а `undefined` из хука означает «оставь поведение по умолчанию». Ошибка в коде не роняет приложение: показывается сообщение, а генерация продолжается с дефолтными правилами.

## Структура

Монорепа на npm workspaces:

- `packages/core/` — логика без Vue: индекс эндпоинтов, резолвер `$ref`, генератор TS-типов, тесты
- `packages/ui/` — UI: компоненты и composables
- `apps/web/` — веб-версия; в `vite.config.ts` живёт middleware `/__spec`, который читает файл или фетчит URL на стороне dev-сервера
- `apps/vscode/` — расширение VSCode
